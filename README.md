# UKreklamy — Кухня реклами

Кастомна WordPress-тема (на основі `reklamy-homepage-concept(2).html`) та окремий плагін для контенту, заявок і Telegram. **Стан: код вимагає перевірки на staging перед оновленням production**, не готовий до публікації без інтеграційного та візуального приймального тестування, юридичних текстів і матеріалів клієнта.

## Локальний запуск

Встановіть Docker Engine / Docker Desktop + Docker Compose v2. Скопіюйте `.env.example` в `.env` і встановіть два сильні паролі (не комітьте `.env`). Запустіть:

```bash
cp .env.example .env
docker compose up -d --build
```

Відкрийте `http://localhost:8080`, пройдіть установку WordPress, налаштуйте мову **Українська**, часовий пояс **Київ**, увімкніть тему **UKreklamy** та плагін **UKreklamy Core**. Якщо 8080 зайнятий, змініть `HTTP_PORT`.

Для зупинки: `docker compose down`. Для повного скидання тестових даних: `docker compose down -v` (**безповоротно видаляє БД та медіа!**).

## Керування контентом

У панелі WordPress: **Послуги → Напрями послуг** — категорії, їхні фото, описи, порядок і видимість. **Послуги → Додати** — окрема підпослуга, назва, повний та короткий описи, ціна від, одиниця, головне фото та додаткова фотогалерея (до 12 зображень), один призначений напрям, прапорець «Показувати на сайті», `Порядок` та статус «Опубліковано». **Портфоліо → Додати** — назва, опис, обкладинка й додаткові зображення (ID із Медіатеки), порядок, статус. **UKreklamy → Контакти UKreklamy** — телефон, Instagram, Telegram, адреса, email, Facebook. Тексти загальних секцій, заголовки, підписи кнопок, форма та SEO-опис редагуються у **UKreklamy → Тексти сайту** (11 груп, 82 поля). Початкові тексти залишаються, доки клієнт їх не замінить. Інструкція: [`docs/PATCH-V1.8.md`](docs/PATCH-V1.8.md).

## Telegram

Створіть Telegram-бота через BotFather, запросіть його в групу менеджерів, дізнайтеся numeric Chat ID (або кілька через кому) й внесіть `UKR_TELEGRAM_TOKEN`, `UKR_TELEGRAM_CHAT_IDS` у `.env` **лише локально** або в змінні середовища хостингу. Бот нічого не обробляє вхідного; тільки `sendMessage`.

## Перевірка форми

Перейдіть до секції «Контакти». Виберіть телефон і введіть справжній номер тестового менеджера або Telegram `@username`; поставте прапорець згоди; надішліть один раз. У панелі **Заявки** відкрийте нову заявку, перевірте статус `sent` або `pending`, кількість спроб, повідомлення про помилки. Для негативного сценарію приберіть токен або вкажіть тестовий недійсний токен і перевірте збереження та retry. Із заданим токеном/Chat ID перевірте фактичне повідомлення. WP-Cron повторює pending щогодини, до 24 спроб. Для надійності в production налаштуйте системний cron — див. `docs/DEPLOY.md`.

Захист: nonce-cookie, SameSite, перевірка Origin, honeypot, 3-секундна пауза, IP rate limit (5/10 хв), UUID ідемпотентності, серверна валідація, очищення даних. Не налаштовуйте публічний кеш HTML головної сторінки без спеціального bypass для форми.

## SEO й безпека

Open Graph/description у темі, sitemap від WP Core (`/wp-sitemap.xml`), robots/індексація в WordPress Settings → Reading. При завантаженні в медіатеку використовуйте оптимізовані WebP/JPEG фото, адекватний розмір та alt. Плагін зберігає лише персональні дані заявки; не давайте редакторський доступ зайвим людям.

## v1.16 — права менеджера, захист заявок, портфоліо Safari

- Після оновлення плагіна WordPress створює роль **Менеджер UKreklamy**. Змінюйте роль клієнтського облікового запису тільки після повної перевірки на staging.
- Права менеджера: власні типи контенту (послуги, роботи, логотипи клієнтів, FAQ), категорії послуг, медіатека, UKreklamy → Налаштування/Тексти/Контакти, SEO-описи в текстах, заяви через **Заявки (перегляд)**. **Немає** `manage_options`, прав на плагіни, теми, користувачів, зміну Telegram-токена та повторну доставку.
- Роботи: `assets-v116.css` додає Safari WebKit 3D-композитинг, стабільну висоту плиток, фотогалерею + опис поруч на десктопі, зручну мобільну верстку та режим reduced motion.
- Форма: honeypot, Origin / Fetch Metadata, обов’язковий таймер, обмеження IP (5 / 10 хв), обмеження одного контакту (3 / год), перевірка довжини JSON, перевірка на сервері, idempotency, захищені заявки та Telegram retries.
- **Cloudflare Turnstile** не активується без пари ключів. Створіть widget для **реального production-домену** у Cloudflare Turnstile, розмістіть `UKR_TURNSTILE_SITE_KEY` і `UKR_TURNSTILE_SECRET_KEY` у змінних оточення (Docker) або в захищеному `wp-config.php` (хостинг). Після цього сервер відхиляє заявки без чинного токена. Пара ключів неповна — відправлення заявок блокується до виправлення конфігурації. Ключі **ніколи** не комітьте.
- Cloudflare DNS proxy і Turnstile — різні продукти: Turnstile може працювати без proxy. Для WAF захистіть `/wp-login.php` (managed challenge / rate limiting), `/xmlrpc.php` (блокувати, якщо не потрібен) та `/wp-json/ukreklamy/v1/lead` (rate limit), але **не блокуйте нормальні POST**. Обмежте доступ до IP origin, оновлюйте WordPress/PHP, налаштуйте резервні копії і 2FA для адміністраторів.
- Заголовок `CF-Connecting-IP` не повинен довірятися при прямому доступі до origin. `UKR_TRUST_CF_IP=true` дозволено **лише після** блокування обходу Cloudflare через прямий IP хостингу. Інакше залиште `false`. При роботі через Cloudflare без реального IP у PHP ліміти для відвідувачів можуть бути спільними — потрібен правильний trusted proxy.
- Не вмикайте публічне кешування WordPress HTML або REST ендпоінтів `/wp-json/ukreklamy/v1/token` і `/wp-json/ukreklamy/v1/lead`. Перевірте Cookie `ukr_form_token`, заявку та підтвердження Telegram.
- Перевірка перед production: `php -l` для всіх PHP-файлів, `node --check` для JS, пробні відправлення з Turnstile / без нього, Safari macOS, Chrome Windows, мобільний Safari, роль менеджера і відсутність `manage_options`. Зробіть backup WordPress БД + uploads + теми й плагіна. Не перезаписуйте робочу БД з development/staging.
- Зміни GitHub **не** означають автоматичного оновлення хостингу: спочатку звірте файлову версію на сервері, потім застосуйте тільки перевірені файли цього PR.
